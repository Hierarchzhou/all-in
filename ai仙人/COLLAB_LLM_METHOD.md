# CollabLLM 协作方法论

> 基于 Radar 2.0 项目的实践总结
>
> 本文档提炼了高效的 AI-人类协作模式，可应用于未来的任何复杂项目

---

## 🎯 核心理念

### CollabLLM 是什么？
CollabLLM 是一种**主动协作式的 AI 工作模式**，不同于传统的"一问一答"：

```
传统模式:
用户提问 → AI回答 → 用户再问 → AI再答 ...
❌ 被动响应
❌ 缺乏连续性
❌ 无进度追踪

CollabLLM 模式:
用户提出目标 → AI主动拆解任务 → AI持续执行 → 实时进度更新 → 主动确认关键点
✅ 主动推进
✅ 上下文连续
✅ 透明可控
```

### 三大支柱
1. **主动性** (Proactivity) - AI 主动推进任务，不等待每一步指令
2. **透明性** (Transparency) - 实时展示进度，让用户随时掌握状态
3. **适应性** (Adaptability) - 理解用户风格，适应其表达习惯

## 📚 学习模式

### 迭代学习循环

#### 1. 项目发现阶段
**用户行为**:
- 提供参考项目（URL、GitHub 仓库等）
- 描述学习目标

**AI 行为**:
- 深度阅读项目文档/代码
- 提取核心架构和设计理念
- 识别可复用的模式

**实践案例** (Radar 2.0):
```
用户: "请分析 MineContext 和 screenpipe 这两个项目"
AI:
  1. WebFetch 获取项目文档
  2. 分析架构、技术栈、设计哲学
  3. 生成 HTML 可视化报告
  4. 提取关键洞察
```

#### 2. 深化理解阶段
**用户行为**:
- 阅读报告后提出关键问题
- 挑战某个设计决策
- 请求更深层次的解释

**AI 行为**:
- 针对问题进行深度技术分析
- 对比多个方案的权衡
- 提供具体的代码示例和实现细节

**实践案例** (Radar 2.0):
```
用户: "screenpipe 如何解决 Vision API 的高成本问题？"
AI:
  1. 识别这是核心技术问题
  2. 创建专门的成本分析文档
  3. 详细解析：
     - MineContext 困境（$864-2,592/月）
     - screenpipe 方案（100% 本地 OCR）
     - 技术实现细节（变化检测、增量存储）
     - 代码示例
```

#### 3. 综合输出阶段
**用户行为**:
- 请求综合性文档
- 明确受众（产品经理、开发团队等）

**AI 行为**:
- 整合所有学习成果
- 按受众需求组织内容
- 提供多种格式（Markdown、HTML、交互式界面）

**实践案例** (Radar 2.0):
```
用户: "创建面向产品经理和开发团队的完整手册"
AI:
  1. 整合 6 个项目的分析
  2. 设计融合架构
  3. 编写 12 章完整手册
  4. 创建 ReactFlow 风格交互界面
```

## 🔄 协作原则

### 原则1: 主动推进 (Don't Wait, Act)

**反模式** ❌:
```
AI: "我已经分析完 MineContext，您还想了解什么？"
[等待用户下一步指令]
```

**正确模式** ✅:
```
AI: "✅ MineContext 分析完成

    我注意到您还提到了 screenpipe，我现在继续分析它。
    同时我会创建对比矩阵，方便您看到两者的区别。

    [开始执行下一步]"
```

**关键**:
- 完成一个任务后，**立即**推进到下一个逻辑步骤
- 不需要等待用户的每一步确认（除非是关键决策点）

### 原则2: 透明可见 (Show Your Work)

**使用 TodoWrite 追踪进度**:
```python
# 任务开始时
[
  {"content": "分析 MineContext", "status": "in_progress"},
  {"content": "分析 screenpipe", "status": "pending"},
  {"content": "创建对比矩阵", "status": "pending"}
]

# 第一个任务完成后
[
  {"content": "分析 MineContext", "status": "completed"},
  {"content": "分析 screenpipe", "status": "in_progress"},
  {"content": "创建对比矩阵", "status": "pending"}
]
```

**好处**:
- 用户随时知道当前进度
- 用户可以随时介入调整
- 减少"你在做什么？"的询问

### 原则3: 上下文连续 (Remember Everything)

**会话恢复能力**:
```
用户: "继续"
AI: [从会话总结中恢复]
    - 项目目标
    - 已完成的工作
    - 待完成的任务
    - 用户的偏好和风格
```

**上下文推断**:
```
用户: "换成中文"
AI: [推断]
    - 最近的操作是 git push
    - commit 消息是英文
    - 用户想要中文 commit 消息
    [执行] git commit --amend + force push
```

**关键**:
- 维护完整的项目上下文
- 理解用户的口语化表达
- 主动推断 + 快速执行（而非过度确认）

### 原则4: 适应风格 (Match the User)

**识别用户风格**:
```python
if user_style == "简洁直接":
    # 减少冗余确认
    # 直接执行明确的指令
    # 用简短的状态更新

elif user_style == "详细谨慎":
    # 每步都确认
    # 提供详细的解释
    # 列出多个选项供选择
```

**Radar 2.0 实践**:
- 用户偏好："简洁直接"（来自 CLAUDE.md）
- 我的适应：
  - 少问"您确定吗？"
  - 多用"✅ 已完成 X，现在开始 Y"
  - 遇到"换成中文"直接执行，不过度确认

## 🛠️ 元规则体系

### 规则1: 任务自动拆解

**触发条件**: 任务复杂度 >= 3 步
**执行动作**: 使用 TodoWrite 创建任务清单

**示例**:
```
用户: "帮我创建 Radar 2.0 项目手册"

AI 自动拆解:
[
  {"content": "分析 6 个参考项目"},
  {"content": "提取设计模式"},
  {"content": "设计融合架构"},
  {"content": "编写完整手册"},
  {"content": "创建交互界面"}
]
```

### 规则2: 并行执行优化

**触发条件**: 多个独立任务
**执行动作**: 单次调用并行执行

**示例**:
```python
# 串行（慢）❌
result1 = await read_file_1()
result2 = await read_file_2()
result3 = await read_file_3()

# 并行（快）✅
results = await asyncio.gather(
    read_file_1(),
    read_file_2(),
    read_file_3()
)
```

**Radar 2.0 实践**:
- 同时创建多个 HTML 报告
- 并行执行 git status + git diff + git log

### 规则3: 渐进式交付

**触发条件**: 长期任务
**执行动作**: 完成一个模块立即标记，继续下一个

**反模式** ❌:
```
[沉默 30 分钟]
"✅ 所有 6 个项目分析完成！"
```

**正确模式** ✅:
```
"✅ MineContext 分析完成，继续 screenpipe..."
[2 分钟后]
"✅ screenpipe 分析完成，继续 DoubleHighC..."
[2 分钟后]
"✅ DoubleHighC 分析完成，现在创建对比矩阵..."
```

### 规则4: 问题驱动深化

**触发条件**: 用户提出技术问题
**执行动作**: 创建专门的深度分析文档

**识别信号**:
- "如何实现...？"
- "为什么...？"
- "X 和 Y 有什么区别？"

**Radar 2.0 实践**:
```
用户: "screenpipe 如何解决成本问题？"
AI 识别: 这是核心技术问题，值得深度分析
AI 行动: 创建 screenshot_cost_analysis.md
  - 问题背景
  - 对比分析
  - 技术实现
  - 代码示例
  - 推荐方案
```

### 规则5: 主动澄清模糊表达

**触发条件**: 用户表达模糊（"这个"、"那个"、"它"）
**执行动作**:
1. 基于上下文推断最可能的意图
2. 如果确定度 > 80%，直接执行
3. 如果确定度 < 80%，列出选项确认

**示例**:
```
用户: "换成中文"

AI 推断:
  - 上下文: 刚完成 git push
  - 最近操作: commit 消息是英文
  - 确定度: 95%

AI 行动: 直接修改 commit 消息为中文 + force push
```

## 📊 实践案例：Radar 2.0 项目

### 项目背景
- **目标**: 创建智能信号雷达系统的完整开发手册
- **输入**: 6 个参考项目的 URL
- **输出**: Markdown 手册 + 交互式 HTML + GitHub 同步

### 协作时间线

#### Phase 1: 项目发现（第 1-2 轮对话）
```
用户: "分析 MineContext 和 screenpipe"
AI:
  ✅ WebFetch 获取项目文档
  ✅ 深度分析架构和设计
  ✅ 生成 HTML 可视化报告
  ✅ 主动开始下一个项目
```

#### Phase 2: 问题驱动深化（第 3 轮对话）
```
用户: "screenpipe 如何解决 Vision API 成本问题？"
AI:
  ✅ 识别核心技术问题
  ✅ 创建专门的成本分析文档
  ✅ 提供详细的技术对比
  ✅ 给出代码示例
```

#### Phase 3: 综合输出（第 4-5 轮对话）
```
用户: "创建完整的项目手册"
AI:
  ✅ 创建 6 项目对比矩阵
  ✅ 设计融合架构
  ✅ 编写 12 章完整手册
  ✅ 创建 ReactFlow 风格交互界面
  ✅ 同步到 GitHub
```

#### Phase 4: 上下文恢复（本次对话）
```
用户: "创建协作记忆文档"
AI:
  ✅ 从会话总结恢复完整上下文
  ✅ 分析本次协作模式
  ✅ 创建项目记忆文档
  ✅ 总结 CollabLLM 方法论
```

### 成功因素分析

#### 1. 迭代学习循环
```
发现项目 → 深度分析 → 生成报告 → 提问深化 → 综合输出
```
每个循环都有**明确的交付物**。

#### 2. 问题驱动
用户的一个问题（成本问题）触发了深度技术分析，这比"全面分析"更高效。

#### 3. 实时进度
TodoWrite 让用户随时看到：
- 当前在做什么
- 还剩多少任务
- 预计完成时间

#### 4. 主动推进
AI 不等待每一步确认，完成一个任务立即开始下一个。

#### 5. 上下文恢复
当用户说"继续"时，AI 能从会话总结中恢复完整上下文，无缝衔接。

## 🎓 可复用的方法论

### 适用场景
CollabLLM 方法特别适合：
1. **复杂项目** - 需要多步骤、多模块的项目
2. **学习任务** - 需要深度理解多个参考资料
3. **文档生成** - 需要整合多源信息并生成结构化输出
4. **迭代开发** - 需要多轮反馈和改进

### 不适用场景
以下场景不需要 CollabLLM：
1. **简单问答** - 一问一答即可解决
2. **单步任务** - 只需执行一个操作
3. **探索性对话** - 没有明确目标的闲聊

### 如何应用到你的项目

#### Step 1: 明确目标
```
清晰定义:
- 项目目标是什么？
- 期望的交付物是什么？
- 目标受众是谁？
```

#### Step 2: 提供参考
```
给 AI 提供:
- 参考项目/文档的 URL
- 现有的代码库
- 相关的技术文档
```

#### Step 3: 让 AI 拆解任务
```
告诉 AI: "请帮我拆解这个任务，并创建待办清单"
AI 会自动使用 TodoWrite 创建任务列表
```

#### Step 4: 主动提问
```
在 AI 生成报告后，提出你的关键问题:
- "为什么选择这个方案？"
- "如何解决 X 问题？"
- "A 和 B 有什么区别？"
```

#### Step 5: 迭代改进
```
基于 AI 的输出:
- 提供反馈
- 调整方向
- 深化某个方面
```

## 🔧 工具使用最佳实践

### TodoWrite 使用指南

**何时使用**:
- 任务 >= 3 步
- 需要追踪进度
- 用户需要可见性

**如何使用**:
```python
# 任务开始时创建
TodoWrite([
  {"content": "任务1", "status": "pending", "activeForm": "执行任务1"},
  {"content": "任务2", "status": "pending", "activeForm": "执行任务2"},
])

# 开始任务1
TodoWrite([
  {"content": "任务1", "status": "in_progress", "activeForm": "执行任务1"},
  {"content": "任务2", "status": "pending", "activeForm": "执行任务2"},
])

# 完成任务1，立即开始任务2
TodoWrite([
  {"content": "任务1", "status": "completed", "activeForm": "执行任务1"},
  {"content": "任务2", "status": "in_progress", "activeForm": "执行任务2"},
])
```

**关键原则**:
- ✅ 完成一个任务立即标记
- ✅ 同时只有一个任务是 in_progress
- ✅ activeForm 用现在进行时

### 并行工具调用

**何时使用**:
- 多个独立任务
- 无依赖关系
- 可同时执行

**示例**:
```python
# 并行读取多个文件
<function_calls>
  <invoke name="Read">
    <parameter name="file_path">file1.md
